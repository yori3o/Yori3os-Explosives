# Проверка ошибок движения снарядов

Дата: 25 октября 2026 года. Проверялся текущий multiloader-проект и фактический код Minecraft из зависимостей сборки.

## Прохождение углов: воспроизведено и исправлено

Обнаружены две отдельные причины.

1. В Minecraft 1.21.1 `ThrowableProjectile.tick()` сначала вызывает обработчик столкновения, затем перемещает снаряд на его новую скорость через `setPos`. Старый обработчик мода дополнительно ставил снаряд в точку попадания и отражал скорость. Следующее перемещение после отражения не проверялось на второй блок.
2. Стандартная проверка брошенного предмета использует луч через его центр. Край бомбы шириной 0.35 блока мог пересекать угол или край полублока, даже когда луч проходил мимо.

Воспроизводимый случай для первой причины:

- Каменный блок: `(256, 250, 256)`.
- Второй каменный блок: `(257, 251, 256)`.
- Бомба: позиция `(256.4, 251.1, 256.5)`, скорость `(1, -0.5, 0)`; гравитация отключена для изоляции столкновения.
- До исправления после одного тика центр бомбы оказывался в `(257.5, 251.1, 256.5)`, внутри второго блока.
- После исправления: `(256.825, 251.0, 256.5)`; габарит бомбы касается поверхности второго блока и не пересекает его.

Для касания края использован полёт вдоль X при Z = 255.9 рядом с блоком, начинающимся с Z = 256. Центр пролетал мимо, но габарит бомбы пересекал блок. До исправления бомба проходила этот участок, после — отскакивает.

Теперь движение использует `Entity.collideBoundingBox`, штатное разрешение столкновений Minecraft для движущегося объёма и voxel shapes блоков. При столкновении отражаются все заблокированные компоненты скорости. Полублоки и заборы учитываются по их фактической форме. Свободное пространство над нижним полублоком остаётся проходимым.

`ExplosiveMovementMixin` заменяет движение только у снарядов этого мода. Общий `Projectile.tick()` сохраняется; остальные брошенные предметы не затрагиваются. Обычные обработчики попаданий, игровые события и отражение снарядов вызываются через `hitTargetOrDeflectSelf`; явная отмена попаданий другими модами через NeoForge также учитывается.

Порядок применения гравитации и затухания унифицирован с 26.x: перед перемещением. Поэтому траектория на 1.21.1 может немного отличаться от прежней. Размер столкновения теперь соответствует зарегистрированным габаритам снаряда, что также меняет самые тесные проходы у поверхностей.

## Другие исправления

| Ошибка | Причина | Исправление |
| --- | --- | --- |
| Липкий снаряд оставался висеть после замены опоры водой или другим несолидным блоком | Проверялся только `isAir()` | Проверяется наличие формы опоры непосредственно у снаряда; при её исчезновении возвращается гравитация |
| Раздатчик выдавал предмет вместо снаряда | Методы `asProjectile` были реализованы, но поведение раздатчика не зарегистрировано | Зарегистрированы все шесть предметов после регистрации предметов загрузчиком |
| Таймер взрыва отставал на один тик | Проверка нуля выполнялась перед уменьшением счётчика | Срабатывание происходит в тик достижения нуля |
| Граната могла выбирать недопустимую живую цель, например игрока в режиме наблюдателя | Переопределение `canHitEntity` обходило фильтр Minecraft | Восстановлен вызов `super.canHitEntity` с сохранением исключения владельца |

## Воспроизводимые проверки

```powershell
python tools/collision_regression.py 1.21.1-neoforge --output build/review/collision-final-1.21.1.json
python tools/collision_regression.py 26.1-neoforge --output build/review/collision-final-26.1.json
python tools/collision_regression.py 26.2-neoforge --output build/review/collision-final-26.2.json
python tools/collision_regression.py 26.3-neoforge --output build/review/collision-final-26.3.json
.\gradlew.bat buildAll
python tools/verify_artifacts.py
```

В каждом сервере проверяются 12 сценариев: стена, касание ребра, касание вершины, скорость 8 блоков за тик, свободный пролёт над полублоком, касание края полублока, край забора, отскок в соседний блок, прилипание, исчезновение твёрдой опоры, настоящий запуск из раздатчика и точный тик взрыва. Дополнительно общий серверный тест проверяет детонацию всех шести видов снарядов и загрузку таблиц добычи.

Исходный сбой записан в `build/review/collision-before-1.21.1.json`; итоговые результаты — в `build/review/collision-final-*.json`. Проверки используют изолированные тестовые миры `run/smoke/`.

Итог: **48 из 48 сценариев прошли** на NeoForge 1.21.1, 26.1, 26.2 и 26.3. Успешно собраны и проверены все восемь устанавливаемых JAR и восемь архивов исходников. Все четыре варианта Fabric успешно инициализировались до запроса EULA; refmap обоих mixin проверен в итоговом Fabric JAR для 1.21.1.

Ручная проверка визуального поведения клиента и сетевых задержек не проводилась. Проверка реального игрока-наблюдателя и совместимости с конкретными сторонними модами также не проводилась. Fabric проверяется запуском до запроса EULA и сборкой JAR; файл согласия тесты не изменяют.
